# 06 美术对接执行方案（美术/外包工作手册）

> 本文件是给美术同学和外包团队的直接作业指南。读完即可开工，不需要再翻代码。
> 配套：数量看文档 04，排期看文档 02，验收流程看文档 05 §7。

## 1. 美术风格指南（Art Direction）

### 1.1 总体风格

- **美式漫画 × 现代像素/手绘混合**：参考《怒之铁拳 4》的干净轮廓 + 《热血物语》的 Q 版比例，角色约 6–7 头身、夸张特征、表情鲜明。
- 政治人物做**夸张 caricature（漫像）处理**，抓标志性特征（特朗普金发、红金战斗服、GOP 盾标；拜登星条盾等），避免写实真人照片，降低肖像权与平台风险。
- 所有角色统一 **2–4px 深色描边 + 色块明暗两阶 + 少量高光**，保证在 720p 小屏和远景下轮廓清晰。

### 1.2 主色板（强制）

| 用途 | 色值参考 | 说明 |
|---|---|---|
| 主角红（共和党） | #C81E1E / 高光 #FF5A4D / 暗部 #7A1010 | 主角与“翻红”阵营 |
| 敌方蓝 | #2B4BD8 / 暗部 #16236B | 被控制区域、敌方 UI |
| 蜥蜴绿 | #3FA34D / 鳞甲暗 #1E5E2C | 蜥蜴人本体鳞片、眼瞳 |
| 能量金 | #F2B705 | GOP 标志、MAGA 终极技、金可乐 |
| 热视线红 | #FF3B2F（自发光感） | 激光、暴击 |
| 中性街景 | 灰蓝 #3A4256 系 | 城市基底，靠红蓝点缀区分阵营 |

交付时附 `.aseprite` 色板或 `palette.png`，全项目共用，禁止私自引入高饱和杂色。

### 1.3 视觉红线

- 不出现真实血腥，命中用火花/星星/冲击线表现；蜥蜴人被击败化为绿色粒子消散。
- 现实政治人物全部漫画化、虚构化处理；台词与符号保持 GDD 的讽刺喜剧基调。
- 所有动画遵循“预备（anticipation）→ 主动作 → 跟随（follow-through）”三段，攻击动作第 2–3 帧为发力帧，与程序判定帧对齐（见 §4）。

## 2. 资源生产管线（从需求到入库）

```
策划提《美术需求单》(§8 模板)
   → 主美出草图/色稿 → 制作人+主程评审（1 个工作日内反馈）
   → 美术做动效源文件(.aseprite/.psd) + 切图 PNG
   → 主美按验收单(§7)自检 → 提交到 assets/art 对应目录(§6)
   → 主美/TA 在 Godot 导入并配 AnimationPlayer → 程序联调判定帧
   → QA 在测试关验证 → 关闭任务号
```

- 每个角色/场景先走 **idle + walk 试稿**，通过后再批量生产全部动作，避免风格跑偏返工。
- 程序侧已预留数据驱动接入点（`CharacterData`/`AttackData`，见文档 07），美术不需要改代码，只交规范资源。

## 3. 角色交付规范

### 3.1 画布与锚点

| 对象 | 单帧画布 | 脚底锚点（以画布左上为原点） |
|---|---|---|
| 普通角色/杂兵 | 256×256 px | (128, 240)，即水平居中、距底边 16px |
| Boss | 384×384 px | (192, 360) |
| 最终 Boss 拜登 | 512×512 px | (256, 480) |
| 道具图标 | 128×128 px | 居中 |
| 头像/立绘 | 512×512 px | 面部居中偏上 |

- 同一角色所有动作帧**锚点必须完全一致**，脚底落在同一基线，否则游戏中会“滑步/跳动”。
- 透明背景 PNG，角色四周留 8–16px 安全边，攻击前伸手/武器可接近边缘但不得裁切。

### 3.2 方向规范

- 移动类动作（idle/walk/dash/hurt/down）交付 **4 方向**：下（面向镜头）、上（背向）、右、左；其中左可由右水平镜像，但**上/下必须单独画**（纵深姿态不同）。
- 攻击/抓投/激光等战斗动作至少交付 **朝右** 一套，程序用 `flip_h` 处理朝左；若动作不对称（如持盾），需另交朝左。
- 文件层面只交“朝右/上/下”，镜像由引擎完成，减少工作量。

### 3.3 帧时长与判定帧

每个动作随附一张《帧表》（可写在文件名旁的 `frames.csv`）：

| 动作 | 帧序号 | 时长(ms) | 备注（程序用） |
|---|---|---|---|
| punch | 1 | 60 | 预备 |
| punch | 2 | 50 | **判定帧（攻击框生效）** |
| punch | 3 | 50 | 判定帧 |
| punch | 4 | 90 | 收招（可被取消窗口起点） |

程序会按“判定帧”开关攻击判定框；美术需在发力帧用最强剪影，方便对齐。默认动画 12–15fps。

## 4. 角色动画帧清单（按文档 04 细化，外包按此报价排期）

### 4.1 主角特朗普（M1 首批，朝右基准 + 移动四方向）

| 动作 | 帧数 | 方向 | 关键要求 |
|---|---|---|---|
| idle | 5 | 4 方向 | 呼吸起伏、披风轻微摆动 |
| walk | 8 | 4 方向 | 重心左右转移，金发与披风跟随 |
| run（并入 walk 加速） | 6 | 4 方向 | 前倾更大 |
| punch_1/2/3（三连段） | 各 4 | 右（左镜像） | 直拳/勾拳/上勾，第 2–3 帧判定 |
| kick | 5 | 右 | 高踢，击倒用，发力帧张力强 |
| grab / hold / throw | 4 / 循环3 / 5 | 右 | 抓衣领、挟持、投掷抛物线 |
| hurt_light / hurt_heavy | 3 / 4 | 4 方向 | 轻击小退、重击后仰 |
| down / getup | 4 / 5 | 右 | 倒地躺平、撑地起身 |
| dash_roll | 5 | 4 方向 | 翻滚/冲刺残影姿态 |
| heat_vision（蓄力/持续/收招） | 3 / 循环 / 3 | 右 | 双眼红光，持续帧可循环 |
| maga_ultimate | 8 | 4 方向 | 起手呐喊→红金冲击波爆发 |
| taunt | 5 | 4 方向 | 标志性手势、夸张表情 |
| hop / fly / slam | 4 / 循环4 / 5 | 4 方向 | 披风推进飞行、空中砸地 |
| transform（普通/觉醒/暴怒） | 各 6 | 正面 | 过场用，配光效 |

### 4.2 杂兵通用模板（8 种敌人共用结构，换皮+微调）

idle 4 / walk 6 / attack 4–6 / hurt 3 / down+getup 4+5，精英与持枪/锁链单位各加 1 个专属攻击 4–6 帧。蜥蜴人需有“鳞片纹理 + 竖瞳”种族统一特征，靠颜色与体型区分兵种。

### 4.3 Boss 通用结构

每个 Boss：登场帧 4、idle 4、移动 6、3–5 个专属技能（各 5–8 帧）、阶段切换变形过场 4–6、hurt 3、down/战败特写 6、对话头像 2–3 张。多阶段 Boss（如拜登 4 阶段）每阶段独立色板或形态，文件名带阶段号。

## 5. 场景交付规范

### 5.1 结构（皮带卷轴固定分层）

世界尺寸基准 **3680×720**，纵向战斗带 Y=472–648（与当前 Demo 一致），必须保证角色在该区域内不被背景“吃掉”。

| 层 | 内容 | 移动速度（视差系数） | 交付 |
|---|---|---|---|
| L0 天空/远景 | 天空、远山、地标剪影 | 0.2 | 整幅或可平铺 PNG |
| L1 中景 | 建筑群、广告牌 | 0.5 | 元件化，可水平平铺 |
| L2 近景 | 围栏、路灯、行人道具 | 0.8 | 元件 PNG |
| L3 地面带 | 路面、人行道、可破坏物 | 1.0（与角色同速） | 64px 网格可平铺 tile |
| L4 前景遮挡 | 路灯柱、悬挂物（可选） | 1.2 | 透明 PNG，用于纵深遮挡 |

- 地面 tile 严格按 **64×64（或 64×32）** 网格绘制，边缘可无缝拼接；路面与上街沿/下街沿分别给 tile。
- 每关提供一张 `preview.png`（整关缩略图）+ 分层文件 + 一份 `layout.txt` 标注：波次生成点、路障位、补给位、Boss 入场区（关卡策划据此配 `.tres`）。
- 场景中可破坏物（车、箱子、垃圾桶）单独切出，2–4 帧破坏动画，轴心在底部中心。

### 5.2 关卡专属要点

旧金山（M1 首关）作为标杆：彩虹涂装街景、坡道、有轨电车、红蓝阵营对比；白天明亮色调，便于验证色板与角色分离度。其余关卡按文档 04 §3 的地点特征出概念草图后再细化。

## 6. 目录与命名规范（入库强制）

```
assets/art/
  characters/
    trump/
      trump_idle_down_01.png ... trump_idle_down_05.png
      trump_punch_right_01.png ...
      trump.aseprite / frames.csv / trump_palette.png
    enemies/lizard_footman/ ...
    bosses/rainbow_phantom/ ...
  scenes/level02_sanfrancisco/
    bg_l0_sky.png / bg_l1_buildings/ / tiles/ / props/ / layout.txt
  vfx/  ui_icons/  portraits/  logo/  store/
```

命名公式（全小写+下划线，禁止中文与空格）：

```
{角色}_{动作}_{方向}_{序号两位}.png
例：trump_walk_down_03.png
    rainbow_phantom_skill_beam_right_02.png
    level02_tile_road_64.png
```

方向枚举：`up / down / left / right`；序号从 `01` 起。源文件与切图同名、扩展名不同。

## 7. Godot 导入与验收检查单（TA/主美执行）

### 7.1 导入设置

- PNG 默认关闭 mipmap，像素风角色关闭纹理过滤（Filter = Nearest）；手绘立绘可用 Linear。
- 序列帧用 `AnimatedSprite2D + SpriteFrames` 或 `AnimationPlayer` 管理，帧时长按 `frames.csv`。
- 每个角色做成独立场景 `{name}.tscn`：根 `CharacterBody2D`（程序挂脚本），美术只管 `Sprite2D/AnimatedSprite2D` 子节点与碰撞盒参考。
- 碰撞/攻击盒由程序根据美术提供的**判定帧参考图**（在帧上用红/蓝框标注）配置，美术交一版标注图即可。

### 7.2 验收检查单（不合格即返修）

- [ ] 尺寸、锚点、安全边符合 §3.1，同角色所有帧脚底基线一致
- [ ] 方向齐全，上/下纵深姿态为独立绘制
- [ ] 描边、色板、风格与风格指南一致，无越界色值
- [ ] 动画含预备/主动作/跟随，发力帧与帧表“判定帧”标注一致
- [ ] PNG 透明无底、无杂边、无裁切；源文件（.aseprite/.psd）与帧表齐全
- [ ] 命名与目录符合 §6，无中文/空格
- [ ] 进引擎后无滑步、无闪烁、循环动作首尾可无缝衔接
- [ ] 在 720p 战斗带内轮廓清晰，红蓝绿色盲友好（必要时加形状区分）
- [ ] 移动端/低端机视角下（缩到 50%）仍能看清动作
- [ ] 授权/著作权凭证归档（外购或外包合同对应）
